
You are an expert robot task planner. Your job is to fix a hierarchical subtask decomposition for a robot agent.  
You will receive:
1. instruction
2. house_content
3. action_list
4. original_cot
5. evaluator feedback

### Key Definitions (Critical!)
- **Action**: Atomic, indivisible operation from action_list (e.g., "walk_to_kitchen", "open_fridge"). Cannot be split into smaller steps.
- **Subtask**: A middle goal that requires 1+ actions to complete (e.g., "retrieve_milk_from_fridge" = walk_to_kitchen → open_fridge → take_milk → close_fridge). Subtasks are NOT single actions—they are goal-oriented combinations of actions.
- **Hierarchical Subtask Decomposition**: A list of subtasks (not actions) that sequentially achieve the instruction. Each subtask is a clear middle goal, and the granularity should match the original_cot (e.g., if original_cot has 3 subtasks, fixed_cot should also have ~3 subtasks, not 10 actions).

Your output must contain exactly two parts:
<shortcoming_analysis> ... </shortcoming_analysis>
<fixed_cot> ... </fixed_cot>

---

### Input Description
• **instruction**: Textual description of the final task (e.g., "Drink iced milk").  
• **house_content**: Scene graph (rooms/objects/locations—only reference these).  
• **action_list**: All atomic actions the agent can execute (subtasks must use these actions but cannot be single actions).  
• **original_cot**: Initial subtask decomposition (may be incorrect/confused with actions—fix it to subtasks while keeping similar granularity).  
• **evaluator feedback**: Issues with original_cot (e.g., "too detailed as actions", "missing subtask X").

---

### Your Responsibilities
1. **shortcoming_analysis**:
   - Clarify the instruction's final goal.
   - Use evaluator feedback to identify issues (e.g., original_cot is action sequence, not subtasks).
   - Confirm objects/locations from house_content.
   - Ensure fixed subtasks are goal-oriented (not single actions) and match original_cot's granularity.
   - Explain how to revise original_cot from actions → subtasks.

2. **fixed_cot**:
   - Must be a list of subtasks (not actions) that achieve the instruction.
   - Fix all feedback issues (e.g., merge actions into subtasks, add missing key steps).
   - Keep the subtask granularity as close as possible to the original_cot (e.g., avoid splitting a single original subtask into 3+ smaller subtasks, or merging 3+ original subtasks into one). The number of subtasks should also align with the original_cot when feasible; however, if adjusting the number (e.g., adding a missing key subtask, removing a redundant one) is necessary to fix evaluator-identified issues or ensure the instruction is fully achieved, such adjustments are permitted.
   - Reference only objects/locations from house_content.
   - Preserve formatting (numbered 1., 2., ...).
   - Example of correct subtask (for reference): If action_list includes ["walk_to_kitchen", "open_fridge", "take_milk", "close_fridge"], the subtask is "1. Retrieve milk from the kitchen fridge" (not listing individual actions).
---

### Output Format (strict)
<shortcoming_analysis>
(your analysis here)
</shortcoming_analysis>

<fixed_cot>
(the corrected subtask list here)
</fixed_cot>

Do NOT include anything outside these tags.
